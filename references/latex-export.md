# Clean LaTeX manuscript export

For a new book, first run the [book format and template preflight](book-format-preflight.md); the specific default font sizes and samples on this page come from an early mathematics book and must not be used directly as the format standard for all textbooks. For programs/formal grammar/annotated code, choose packages and native structures according to [Code and special text](code-special-text.md), and verify actual export capabilities first.

Export from the single revised semantic data `blocks.jsonl` and the accepted `figures.json`; the original text/styles/sources stay unchanged, and numbering, references, layout, and source-image corrections apply only to the rendered copy and are recorded in the sidecar. Do not maintain another body text from Markdown mixed with HTML.

## Native syntax and template

Prefer existing packages, then standard commands, and only lastly custom macros that are truly necessary. For dashed column separators in augmented matrices, use standard arydshln (loaded after array/cellspace; ordinary tabular uses standard ADLinactivate to preserve the cellspace paragraph box, and math array uses ADLactivate), keep the colon in the native array column specification, and do not force the matrix into a grid or modify matrix data. Configure global appearance only in `assets/latex/book-style.sty`: ctex headings, geometry text block, fontspec fonts, amsmath numbering, amsthm end marks, caption figure/table captions, array table parameters, hyperref links. For math headings, use hyperref's native texorpdfstring to separate the visual math heading from the safe text bookmark, avoiding errors when boldsymbol and similar commands expand in a PDF string; body headings and styles are unchanged, and unknown math commands keep their literal form in the bookmark without guessing meaning. Chapter source code should read as ordinary `chapter/section/subsection`, `equation`, `figure/table`, `caption`, `tabular`, `multirow/multicolumn`, `label/ref/eqref`, and `minipage`; do not generate dedicated wrapper functions for each cell or figure.

The bundled template's font sizes and heading settings are only an adjustable starting point; calibrate them against representative source pages, the reading goal, and actual compiled pages. Use `\textbf` for ordinary semantic emphasis; fontspec's BoldFont maps to a font explicitly chosen for the current document and actually available; mathematical bold remains a math macro. Italic and inferred provenance follow the font contract.

```bash
python scripts/export_latex.py \
  --blocks /absolute/work/book/blocks.jsonl \
  --figures /absolute/work/book/figures.json \
  --manifest /absolute/work/prepared/manifest.json \
  --source-pdf /absolute/original-book.pdf --expected-pages 1-50 \
  --format-profile /absolute/work/format/book-format.json \
  --template-ready /absolute/work/format/template-ready.json \
  --output /absolute/work/latex/dist \
  --build-dir /absolute/work/latex/build \
  --sidecar /absolute/work/latex/export-manifest.json \
  --title 'Book Title' --author 'Author' \
  --nominal-page-mm 170 --text-width-mm 164 --figure-scale 1.4 \
  --cjk-emphasis-font 'SimHei' \
  --figure-layouts /absolute/work/figure-layout-decisions.json \
  --covers /absolute/work/covers/covers.json \
  --table-presentations /absolute/work/table-presentation-decisions.json \
  --proof-endings /absolute/work/proof-endings.json \
  --numbering-overrides /absolute/work/numbering-overrides.json \
  --compile
```

Original table lines and per-table widths must be source-reviewed; exporting body text that contains tables must provide `--table-presentations`. Other special layout/marker decision parameters may be omitted; do not guess special positions without evidence. `--expected-pages` is required and supports `1-50,53`; the original PDF must match the source hash and must not be a temporarily cropped PDF. Source export does not need TeX; compilation requires XeLaTeX, ctex, geometry, fontspec, amsmath/amssymb/amsthm/bm/mathrsfs/cases, graphicx, array/cellspace/arydshln/booktabs/multirow/tabularx/adjustbox, float, caption, needspace, pdfpages/multicol, titletoc, hyperref, and installed fonts. The defaults are Noto Serif CJK SC/Noto Sans CJK SC/Noto Serif/Noto Sans; you may adjust fonts explicitly without changing system configuration.

## Automatic table of contents

Use native `tableofcontents`; entries come from body-text headings and page numbers come from compilation; the original table of contents is used to verify inclusion scope and appearance. Unnumbered sections, optional-reading asterisks, page-number column font size and fixed width, uniform page style, front-matter Roman/body Arabic numbering, compile convergence, and jump acceptance are collected in [Automatic table of contents reference](contents.md). Table-of-contents revisions reuse the current semantic data and do not re-OCR.

## Source package and drawing code

Deliver figures together with their final drawing code; include the necessary spec/data, shared renderer, frozen style, and fonts; projects that retain source images do not need a fabricated redraw script. `package_latex.py` packages after acceptance and can actually replay to verify; for the directory structure, parameters, and checks, see [Source packaging](source-package.md). Work logs, candidate figures, and compilation auxiliary files remain outside the package.

## Numbering and references

For equation systems numbered line by line inside a left brace, use the mature `cases` package's native `numcases`, bind a `label` on each row, and let the equation counter increment normally; if the package reuses the same hyperlink anchor for the whole group, create independent targets on each row with hyperref's native `phantomsection` and test the actual PDF jumps. Accept only a `numbered_system` contract confirmed against the source image (complete original-formula hash, source image hash, all rows' math content/original numbers/source-block ownership); do not guess numbering from digits in an ordinary array. Numbering metadata and targets are written to the export sidecar, and the original text is not changed; only the rendered copy removes handwritten numbers on each row. Enabling a new math package requires regression-testing the book's existing aligned/array, not just the minimal example of the new equation system.

`latex_numbering.py` builds a stable ID → original book number → LaTeX label index for each source heading/figure-table caption/display formula. For headings that already have numbers in the original book, strip the printed number first, then generate them with the standard unstarred heading command; convert an ordinary source tag on a formula to equation, keep unnumbered formulas as equation*, and use caption for figures and tables. Process multiple display formulas within one block one by one, each with its own label; do not generate only one equation number per block. Counters must agree with the original book numbers; when they are non-consecutive, use setcounter only where necessary; when a sample starts in the middle of a chapter, provide explicit chapter context first and do not guess the chapter number from physical pages; contradictions in hierarchy/chapter numbers or duplicate targets are rejected, and the original book numbering must not be changed silently.

Use `thechapter-arabic` for figure and table numbers and `thechapter.arabic` for formulas; the format is determined by the template. Use eqref for ordinary formula references, ref for chapter/section/figure/table references, and hyperref for jumps. Keep chapter/section/figure/table references in a native mbox so the short number stays unbreakable as a unit, preventing a narrow column from splitting "图3-3" across two lines; link targets are unchanged. Replace only references with clear context, such as "图2-1", "表1-1", "由(2.12)式", and "1.2节"; do not treat isolated decimals or mathematical expressions as references. References outside the current sample keep the original text and are recorded as unresolved; do not create broken links; the original table of contents and printed page numbers retain provenance data, and the reading table of contents automatically generates actual page numbers according to the previous section's rules.

Numbers of the form `(1.1)′` in the original book are a few local exceptions: do not advance the ordinary equation counter; construct the original display number with AMS tag* and a reference to the base formula, then give it an independent label. When referencing the entire special tag, wrap the display marker generated from the base formula number with hyperref; do not apply eqref to the complete parenthesized tag again, which would produce double parentheses. When the source image confirms that the OCR prime position is wrong, use the explicit `--numbering-overrides` review list, containing block_id/display_ordinal/source_number/prime_position, source/source-image/text hashes, and review; currently only prime position is supported, and arbitrary renumbering is not authorized. Math content is unchanged, and the original source marker is kept in the sidecar.

## Body-text and style boundaries

First isolate math tokens, then escape ordinary `% & _ # { } $ ~ ^`, and parse Markdown emphasis and allowed HTML text styles; do not perform global replacement on the output TeX. Support explicit paragraph/formula/heading/list/theorem/proof/example/exercise/caption/table/figure/code/grammar/display_group; headers and footers do not enter body text, but the reason for ignoring them is recorded. Unknown HTML/inline images, mismatched closures, dangerous math macros, and similar problems raise errors; do not secretly change formulas to make compilation succeed.

`styles` uses Unicode ranges in the original `text`. Some math styles must already be encoded as math macros; unreviewed candidates remain in the workspace and must not falsely claim a normal font or confirmed bold. Native math macros remain. Full-width math punctuation uses explicit text encoding; missing glyphs such as circled numbers and Roman numerals use native fontspec fallback, including bare math circled numbers and circled numbers inside existing `\text` arguments; horizontal/vertical/diagonal ellipses use cdots/vdots/ddots respectively, and ordinary text wraps them in ensuremath. Map only known glyphs; do not guess or change fonts for math letters; the sidecar records source characters/offset/hash and fallback. Trimmed styles for numbered headings use the original offset record without changing the original JSON. Reviewed `inline_label` bindings such as "例/解/证明/定义" (Example/Solution/Proof/Definition) insert `\hspace{\ccwd}`, one Chinese-character width, at render time; they do not use ordinary spaces and do not match body-text words with the same name. A label requires the original text hash, range, rule ID/version, and source review; it is rejected once stale.

Keep a short lead-in paragraph together with the immediately following display formula using standard `\nopagebreak[4]` (without inserting \par first), to avoid the lead-in sentence being orphaned after a page break; preserve the complete source paragraph/formula, do not page-break manually at a particular sentence, and do not seal a long paragraph or an entire proof into an unbreakable box. The current conservative threshold is an original paragraph of no more than 100 characters; when it actually overflows the page, re-check the source structure and formula segmentation.

### Spacing above and below display formulas

A display formula continues the lead-in sentence above it; at export, only start a new source line before the formula, without inserting a blank paragraph; `equation` itself handles the display transition. Mechanically adding a blank line to every semantic block, or placing `\par\nopagebreak` before the lead-in sentence, makes AMS see vertical mode and produces extra blank lines/line height, which must not be masked by merely reducing abovedisplayskip. This rule applies to body text, in-paragraph display formulas, footnotes, and the right column of table text alike. A genuine new paragraph after a formula is still preserved, and math content, labels, and source Unicode offsets are unchanged.

The template sets abovedisplayskip/belowdisplayskip to 4pt at body size, 3pt at small size, and 2pt at footnote size, without stretch. For TeX's short-line branch, abovedisplayshortskip/belowdisplayshortskip are 0pt: native baseline clearance remains, without adding an extra blank band. Size-command hooks alone do not reliably retain these settings after ctex/fontspec changes; append BookSetDisplaySpacing to the existing everydisplay token list so the actual effective font size determines spacing when display math starts. Keep AMS tokens already in everydisplay; do not replace the token list or add per-formula negative spacing. Verify actual ink gaps after headings, zihao/normalsize, small/footnote transitions, and in lists/narrow columns. The reading template uses raggedbottom to avoid flushbottom enlarging local whitespace, rather than per-formula negative vspace. Set arraystretch=1.25 only in the tabular scope; it must not globally affect math array or create extra whitespace above struts inside formulas.

Actually compare the ink gaps outside formulas with the source image, not only whether the four skips are equal: fractions, superscripts/subscripts, and cases/array have different box heights/depths and visible glyph boundaries, so you must not promise pixel-identical whitespace for every formula. Preflight includes at least short/long lead-in lines, a simple single-line formula, a fraction/multi-line formula, footnotes, and narrow columns; check that lead-in orphan prevention still works, that parameters remain consistent after the font size returns, and that book-wide pagination has no omissions.

For long inline lists, prefer native optional line breaks; do not shrink the font size of the whole paragraph or hide overfull boxes. For long inline expressions of at least 30 characters, the exporter adds a native \allowbreak before the start of the math; for lists or long expressions with at least two breakable commas, it provides \penalty1000 discretionary points at the top level and after commas inside ordinary parentheses, preferring to keep the expression complete. The sidecar records the original math range/hash and the rendered break points; do not touch display formulas, macro arguments, fractions, escaped commas, square brackets, or left/right unbreakable boxes. After actual typesetting, check grouping semantics, math glyphs, and whether line breaks are clear; if still too wide, review the source structure and do not arbitrarily change it into a different formula.

## Proof end markers

A proof should ideally become a real proof environment at the semantic stage; when the original book has an end square, use amsthm to place the QED, and when the last line is a display formula, use qedhere inside the environment. Do not guess that a proof ends merely because an ordinary □ appears in the body text. A detached/trailing square in legacy data may be bound to the last complete paragraph through source-reviewed `--proof-endings`, outputting the standard `\qed` without starting a separate left-aligned line.

The square count must include the top of the original page: a proof may end on the previous page while the square was split by scanning/OCR to the top of the next page. Verify source-image candidates, semantic bindings, and the number and position of squares in the actual output; do not rely only on same-page line geometry filtering; cross-page binding still requires source-image and complete-final-paragraph evidence.

The binding is schema_version=1/source_sha256/proof_endings list; each item has mark_block_id, anchor_block_id, kind=standalone or terminal_inline, marker_start/end/text, marker_text_sha256 (the entire mark block), anchor_text_sha256, source_image_sha256, and review.source_checked/reviewer/evidence_path. A standalone marker must be immediately adjacent to the anchor; a terminal marker must be at the end of the same paragraph; both source IDs retain one provenance mapping each. The binding accepts a normal paragraph/proof/example without footnotes, the final step of a flat list without items, or a formula; allow standard math-wrapped \(\square\) and source-reviewed \Box, and still require the original marker range/hash and source_checked. When the square is inside a display formula, remove only the reviewed range and preserve the math closing symbol and style offsets; at the end, a math closing symbol is allowed but no following content is. When the end is actually a display formula, use native pushQED/qedhere/popQED; for an unnumbered whole aligned formula, use native align* so the QED sits at the right edge of the text block on the last line. When a complex array, numbered formula, and square position occur together, verify the actual output, do not mistake the right edge of an internal box for the right edge of the text block, and do not change the original book numbering or math source.

## Tables

Prefer a `cells` row-by-row list, where a cell is text/rowspan/colspan/align(c,l,r)/valign(c,t,b)/styles; HTML tables and pipe tables are also supported and are used to build a two-dimensional grid. The header role is not automatically bolded. The source `table_layout` schema1 records row/column counts, source image/text hashes, source_checked evidence, and horizontal/vertical line segments, each with a half-open boundary/start/end range, single/double, and width_pt. Verify unknown lines against the source image first; do not turn every table into a three-line table or a grid. Lines through merged cells, duplicate segments, and invalid ranges/hashes are rejected; vertical lines are currently fixed at 0.35pt, and special line styles retain the source image or use a suitable package instead.

Write a stable vertical line for an entire column once in the column specification; use multicolumn only for genuinely merged cells, local vertical lines, or different alignment, and multirow for row spans. Use hline/cline directly for ordinary boundaries; do not repeat macros for every cell. Choose the width per table according to the original page: for full width/source narrow width, use native tabular's fixed-width m column (array package, centering/arraybackslash, vertically centered); for natural width, use c/l/r; when the original book has a clear ratio/two-column relationship, fill the corresponding narrow column according to source_width, use tabularx for long text, and longtable for cross-page tables. Not every table is stretched, and not every table is forbidden to stretch. Font size and caption spacing are unified by the template, and table width/position are controlled by source-reviewed metadata; do not change fonts per table by feel or hard-code figure numbers. caption[table] is uniformly placed above, skip=5pt, avoiding large whitespace from nested center/medskip; a standalone table[H] keeps caption and table together, and in-body embedding uses standard minipage/captionof{table}. If compilation reveals overflow/oversize, adjust the appropriate package and data structure; do not hide rows or columns.

`--table-presentations` provides a schema_version=1/source_sha256/tables list and optional groups, source-reviewed per-table width_policy=full_width/natural_width/source_width and width ratios, source/text/image hashes, and review. `table_presentation.py` checks the rules and text_table embedding groups; source_width is converted to mm according to the uniform text-block ratio, without multiplying by a ratio again inside local columns. Natural width uses intrinsic column widths and does not shrink the font; if the available width is exceeded, first adjust the standard column type or re-check the source image. When the original table has positional relationships but cannot be embedded reliably, explicitly keep the narrow table standalone instead of stretching it to full width.

`column_layout` is per-table source-reviewed column metadata: `column_width_weights` must match the number of semantic grid columns, and column_alignment, source/text/image hashes, review evidence, and the original line-topology hash are all verified. A source table with equal columns starts from equal weights, and a source table with unequal widths starts from the original boundary ratios; do not apply "all equal" uniformly; these are initial values for the reading-edition layout, not a constraint forbidding post-review width adjustment. For a fixed column, take the full table width minus the actual arrayrulewidth/doublerulesep as the area, then subtract tabcolsep on both sides proportionally; compute with standard dimexpr and template lengths, not Python hard-coded padding that global settings then change. Natural column width only guarantees that the column's own content is centered and must not be used to claim equal columns.

Among the 10 semantic grid columns of Table 1-1, 4 columns are auxiliary arrow areas beside numeric values, not 10 physical columns; `column_layout` records 6 physical groups and 4 auxiliary columns. Use native @{} to remove duplicate padding only inside the owning numeric/auxiliary area; keep the outer tabcolsep whitespace, and do not delete numbers/arrows or single/double lines. Use a real multicolumn for a spanning heading, with the merged width computed from the total ratio of the owning columns; do not repeatedly wrap every ordinary cell in a macro. When long content truly needs wrapping, use a p column, but first check whether width can be freed from n and other short-content columns or from columns with lots of whitespace, eliminating unnecessary header/short-equation wrapping; do not accept a wrap that is easy to fix just because it is "readable". Only when no feasible allocation exists, keep natural wrapping and explain it. Do not shrink characters, truncate symbols, change real merged cells, or cover adjacent cells with zero-width boxes.

### Reading-edition column-width adaptation and font-size acceptance

First freeze the book-wide base font size for tables, then inspect all text, numbers, fractions, and subscripts at actual PDF scale. The current template hooks the native tabular environment to unify small (10.5pt), arraystretch=1.25, extrarowheight=2pt, and everymath's displaystyle, preventing inline frac from reducing the numerator/denominator to about 7pt; it applies only to tables and does not change the math source or scale the entire table. After fractions become taller, re-check row height, rule distance, embedded-group height, and pagination; use array's native m column for fixed columns; through the cellspace package's S{m{width}} (S{c/l/r} for natural columns), guarantee at least 3pt whitespace above and below based on the real cell box height/depth, avoiding tall fractions touching rules or overlapping the next row. For a row-spanning cell with explicit br line breaks, use native width= for fixed-width multirow and preserve column alignment, and shortstack for natural width; do not put it in multirow's single-line * box, which disables line breaking. Do not assume arraystretch or merely adding extrarowheight covers all tall/deep math boxes. cellspace uses nomath and does not change body-text matrices. Row-height parameters likewise take effect only in the table scope and must not leak into body-text math array.

The source `column_layout` keeps the original record. When column-width allocation truly needs improvement, store a separate `rendered_adaptation` in the same table presentation: `column_width_weights` covering all semantic grid columns, `source_sha256`, `text_sha256`, `reason`, a positive integer `iteration`, and `review.rendered_checked=true`/reviewer/`evidence_path`/`evidence_sha256`. Evidence means a PDF or rendered image that was actually inspected, and the file hash must be valid; it proves the basis for the revision, not that the new output has passed. The exporter uses only the new weights to choose column widths and does not change the total table width, borders, data/order, real spans, or auxiliary-column ownership. Each round's new-output PDF hash, screenshots, issues, and re-verification results are stored in a separate review record.

Allocate width according to content needs: measure the longest heading/unbreakable short equation plus padding on both sides, then free space from surplus columns, keeping reasonable symmetry and centering. A short column need not be as wide as a long heading; fractions in narrow-table embedding must also remain readable, without template branching on table number. When total width is insufficient, first re-check the layout/surrounding text space or standard column environments; necessary wrapping is acceptable, and you must not mechanically pursue zero wrapping.


Independent left/right sub-tables retain one original semantic owner and the original text; do not silently join multiple HTML tables into a long table. The presentation's `table_parts` items each contain the original text's Unicode `text_range`, fragment text_sha256, source_bbox_px, that sub-table's table_layout, and a standard single-table presentation (owner ID retained, caption_block_id=null, column widths/hashes specific to the fragment); the outer level retains the full text/hash/total bbox/original caption and provides parts_gap_fraction. Check that the ranges cover the original text exactly once excluding whitespace, check the left/right source geometry and each complete sub-table's independent line topology, and render two native minipage/tabular inside one table/caption; the source owner is consumed only once. When independent sub-tables have different row counts but the source aligns their top and bottom, after actual measurement you may give the source-reviewed single-table presentation's row_spacing_pt as a per-row list (length row_count, 0..24pt), using native \\[Npt] to distribute the extra height; do not mechanically increase header height, and do not change font size/cell content/line topology; after recompiling, verify that the bottom edge and center lines close. Unreviewed multi-tables are rejected and not silently flattened; actual font size, misaligned row groups, and height still require output acceptance.

## Figure scale and grouping

Freeze the source canvas/display_width_mm; map uniformly as `source image width / nominal page width × textwidth × figure_scale`, with proportional height. The exporter computes the figure width once and emits a fraction of the current linewidth; plan grouped figures at the same scale and do not multiply by the local minipage width, which would shrink them twice. The default 1.4 is a starting point for the current reading template; before export, verify it against representative figures' fonts/line widths/side-by-side space, and do not claim it suits every book; keep all figure width ratios and do not fill each figure independently. Apply the same figure_scale book-wide first; if a single wide figure exceeds the text block, use native includegraphics' max-width policy to limit it proportionally to the text-block width; non-oversize figures are unchanged, and do not arbitrarily fill or shrink each figure. The sidecar records requested_width_mm/actual_width_mm/width_fit_factor/effective_figure_scale. Wide figures must have fonts/line widths compensated uniformly at the drawing stage according to the final fit factor, and verify that the main text is about 9pt and subscripts at least 6pt; do not merely auto-shrink and then claim readability. If the total width of a multi-figure row exceeds the text block, still re-check the grouping or fall back to the complete order; do not crop figures/captions.

The explicit `--figure-layouts` verifies the source bbox/hash, the caption binding for each figure, the complete paragraph text plus cross-page provenance and source left/right or horizontal bands. Use native minipage and captionof to keep side-by-side or text–figure two-column layouts; output the whole group's content only once per run, with no duplicate definitions/fallback branches. At the planning stage, do not group narrow columns/overlong paragraphs/footnotes; preserve the complete source order and record it. If the actual output overflows the page or text is obscured, modify the plan and re-export; do not truncate body text; both compilation and visual audit must check group height. A small QR code at the end of a chapter and a short preceding paragraph (including the final step of a flat list with no items/footnotes) may be kept together with a standard minipage without adding a new figure number; choose according to role, same original page, size, and the no-display-formula guard, and actually check to avoid the QR code occupying a blank page alone.

For multi-paragraph text–figure two-column layouts, use a complete `text_blocks` description list (consistent with the table-text scheme): each item has block_id, text_sha256, source_block_ids, source_bbox_px, and cross-page reviewed_text_sources; it may contain paragraph/formula and source-reviewed example/proof/theorem (retaining the original type and structural label); `text_block_ids` must agree with the descriptions and semantic order, and source_text_bbox_px must equal the union of the complete bboxes. The legacy single-paragraph text_block_id contract is still supported. Checks for per-source hashes/complete blocks/adjacency and exactly-once consumption are not relaxed; do not discard body text or change the original text through merging for embedding; if the actual column is too narrow, the content too long, or a footnote is present, fall back to the complete order.

The main text, subscripts, and fractions inside a figure must be accepted in the final PDF at the actual embedded scale. The current target is main text about 9pt and subscripts at least 6pt; use Matplotlib mathtext's dfrac for fraction function annotations (same meaning as the source) to avoid shrinking again internally. Do not verify only the large PNG. Each figure ends with exactly one selected PDF/PNG; provenance, drawing script, data, self-check, and revisions remain in the workspace; figure labels are stored separately as AI retrieval data.

## Covers, footnotes, and provenance contract

For a new book, first ask whether to use a full source-image page (default) or a concise cover with verified information; do not ask again once the choice is made for the same book. `prepare_covers.py` verifies the real page roles/range/complete manifest/source hash/review, and that each page's native PDF agrees with the source geometry/hash. Source-image mode uses native includepdf to display the whole page proportionally, with pagecommand clearing headers and footers, without cropping or stretching; copy only the covers in the current range, without extra OCR/decorative splitting. Concise mode uses native titlepage and fills only verified fields. All elements of the original split cover map to the whole page and are not displayed twice.

`footnotes` are source-reviewed explicit anchor/marker ranges, complete child blocks, and review; the marker range must match the original text, and offsets must be correct when merging across pages. Render native footnotes, preserving the original printed marker and complete math/styles; a marker repeated in the first child block is removed only at render time; each child source ID maps uniquely, and duplicate top-level or recursive footnotes are not allowed. For complex footnotes inside captions/display formulas/table headers, explicitly choose a suitable package; do not guess placement.

Every block has a unique stable ID, a uniform source hash, and a valid page/sources; the set of physical pages exactly equals expected-pages, and the manifest's complete status/range is cross-checked against the source file hash. Input is not inside output, and sidecar/build are not inside dist; overwriting is rejected by default, and force only replaces explicitly. The original text, font candidates, mapping of each source ID to TeX lines, counters, reference bindings, source-image revisions, figure scale/assets/hashes, and compile commands/times/diagnostics are all in an external sidecar.

## Delivery and acceptance

By default dist contains main.tex, book-style.sty, book-config.tex, .latexmkrc, BUILD.txt, chapters/*.tex, exactly one images/*.pdf or png per figure, the selected covers/*.pdf, and the successfully compiled main.pdf. The editor hints and latexmk configuration select XeLaTeX; BUILD.txt explains compiler selection and the configured external body-font dependencies. Font files are not automatically included with the body source; the portable drawing-font bundle is separate. build/logs/aux, working JSON, source page images, HTML, candidate figures, and scripts do not enter dist; the AI retrieval package is exported separately.

The first template preflight must include representative real elements such as hierarchical headings/Chinese emphasis/math labels/source table lines/figure sizes/footnotes, and must actually render before dispatching the full text. Typesetting revisions reuse semantic data and must not re-OCR the whole batch; after deterministic export and two compile passes, audit the segmented ranges in parallel, with the coordinator reviewing the whole-book overview and comparing against source images. A standard-package compile passing with zero missing glyphs/overfull still does not prove that OCR content or typesetting aesthetics are correct. Each chapter/figure worker first does bounded self-iteration following actual render → view the image → fix, then enters the main thread's whole-book summary review; the main thread lists issues and then dispatches fixes in parallel, recompiles, and re-verifies, with a default limit of 3 revision rounds each, prioritizing the job budget. If problems remain at the limit, list them as pending fixes and do not claim everything passed. Job ownership and the issue queue follow the [parallel workflow](parallel-workflow.md). Perform the actual overall PDF audit according to the [evaluation rules](evaluation.md): real heading size/centering/chapter spacing, QED position, table caption spacing/table width/original lines, in-figure text and left/right side-by-side, original book number consistency, and reachable bookmarks and links. Fix global defects in the template; for source-data defects, fix the render contract only with source-image evidence; record local exceptions separately.

Content uncertainties are kept in the uncertainties/source index, and internal block IDs are not inserted into math formulas. When remaining compatible with `\text{[待核查：source_id]}` in existing data, it must match this block's source ID and a unique uncertainty record one-to-one; remove this working marker only in the rendered copy and add a standard small-text "textual note" plus a footnote hint after the formula, recording the original hash/offset/reason. Footnote numbers must not sit tight against digits and cause misreading as exponents. Defects in the original math that still cannot be transcribed must not be hidden for this reason; multiple markers or a missing matching contract must be planned explicitly, not silently deleted.

## Back matter and algorithm steps

The whole book's exercise answers, references, and index must not continue body-text automatic chapter-number inference. `assemble_book.py --document-parts` reads an explicit source-reviewed contract: schema_version=1/source_sha256/parts, each part with a unique back-* part_id, role(answers/references/index/appendix), consecutive pages, source title, columns(1, or 2 for index), and review with source_checked/reviewer and per-page native evidence_path/evidence_sha256. When a real footnote on the original title has a different syntactic representation, list it explicitly in the source-reviewed title_variants; do not strip digits/circled numbers generically. Each page's evidence must match the prepared source image hash; partial overlap, missing evidence, or an old contract is rejected.

Assembly only attaches the document_part structure and contract hash, without changing text/styles/sourceIDs. Headings inside back-* use native starred chapter commands; the first heading gets a native label and addcontentsline to create a bookmark, and moving arguments use the source title without footnotes to avoid duplicate footnotes; `第N章` (Chapter N) in answers uses local subheadings rather than a new body-text counter; the back cover is a separate back-cover page and does not enter the index columns. Export re-verifies the source image, contract, complete page ownership, and unique first heading; the index uses multicol's native multicols(2) after the complete heading, flows in the verified original reading order, and keeps printed page numbers without arbitrarily changing them to typeset pages. The template's local multicols environment uses small, parindent/parskip of 0, and centered letter-group headings at the same size and compact; the native environment grouping restores body-text settings, without adding whitespace per entry. Finally check letter-group sizes, column width, entry wrapping, and bottom completeness.

A real source footnote on a heading uses native footnotemark/footnotetext, placed at the heading and the page bottom respectively, and the bookmark uses hyperref's native texorpdfstring; do not stuff an ordinary footnote directly into a moving heading argument and lose body text. Preserve the original circled number, body text, source ID, and range of the footnote.

The hierarchy of algorithm flat list/paragraph may attach a source-reviewed list_presentation: schema_version=1, source/text/image hashes, complete source_block_ids, indent_ccwd and optional hanging_ccwd, with review containing source_checked/reviewer/actual original-page evidence_path. Native parshape expresses first-line/continuation indents and resets at the end of the natural paragraph; do not force insertion of \par or a blank paragraph before a following display formula, which creates extra top spacing, and do not let it leak into subsequent ordinary paragraphs; do not automatically guess levels from numbers or renumber. Indentation at each level is based on this run's source review and the final text block, not measurements reused from other documents. Check hierarchy, consecutive lines, in-list math, and available width in the actual PDF; shrinking characters or omitting steps is forbidden. A mixed formula containing native math delimiters first goes through math lexical parsing; do not stuff \(…\) into equation again, causing nesting; if source display lines/right numbering require syntax normalization, use an explicit before/after source-reviewed patch that preserves the original math and raw output, and do not guess formula numbers from parenthesized digits.

## Generic structure and code entry points

The exporter is wired to the shared semantic_contract: reviewed paragraph_presentation controls continue/new_paragraph and an independent first_line, so a formula with text before and after in the same paragraph does not produce a TeX blank line due to OCR block boundaries; unknown remains unresolved. heading_presentation distinguishes real chapters/sections from local_heading/algorithm_label; local headings use source-reviewed font size/outer indentation, preventing numbering characters from automatically raising the level or entering the table of contents. Nested items and explicit marker/label use native enumitem; the legacy flat algorithm list_presentation still retains source-review restrictions. styles supports independent underline/kai, keeping Chinese Kai separate from Latin/math italic.

code/grammar/display_group generate native code, native grammar, and comparison groups through special_text; the original text is unchanged, the raw UTF-8 file and the rendered file each have a hash, and the provenance sidecar keeps assets and structure. Use fvextra/fancyvrb, native amsmath structures, standard minipage, and necessary TikZ braces; currently only right-side non-wrapping annotations are supported, grammar requires explicit safe LaTeX or literal alternatives, and unsupported capabilities are explicitly rejected. TikZ here is used for code annotations and does not mean that TikZ/SVG execution backends for all figures have been implemented.

Production export uses the current source-bound `--format-profile` and an accepted `--template-ready`; trial typesetting may pass `--preflight-mode`, with at most 8 actual source pages and an explicit non-production status, and the profile must still be valid. The actual template and tools used for trial typesetting must match the frozen identity in ready; any modification requires recompilation and source review before publishing a new ready. Preparing this book's rules does not mean all their fields are executed automatically; for supported entry points, see [Format preflight](book-format-preflight.md).

When this book has unnumbered "definitions", an explicit inline_label may preserve one-Chinese-character label spacing; automatic annotate rules require source review and must list `unnumbered_labels=["定义"]`, and must not treat the same word in ordinary body text as a label.

Adding list/body-text underlines requires enumitem and ulem; explicit kai selects an actually installed Kai font through `--cjk-kai-font`. Local heading fonts use native grouped commands; term labels use textbf, and the template controls labelitemi and enumitem defaults. Do not require a private Book font/list protocol from a user template. Fonts in the code profile must be registered through Fancyvrb's actual font entry, and fontspec command names must not be treated as NFSS font families; acceptance should check the actual PDF fonts, not just the configuration JSON. Only code font size/line spacing/default outer indentation are loaded automatically from supported_template_rules; other descriptions must still be implemented in the book template.

When structured lists have no explicit `labelwidth_ccwd` or `hanging_ccwd`, the renderer measures every rendered label at the active font size and reserves the widest label plus the label/body gap. This includes automatic enumerate labels at each native level; explicit reviewed geometry still takes precedence. Check the visible ink against the text boundary: full-width punctuation's extracted bounding boxes include blank side bearings, and a label protruding into a margin may produce no TeX overfull warning. A description term has no bullet unless its `marker` explicitly supplies one. The default template controls topsep/partopsep/itemsep/parsep/listparindent through enumitem setlist; zero partopsep prevents a source blank line from adding an extra list gap, and a two-character listparindent distinguishes additional paragraphs inside an item. Plain multiline legacy list text does not establish item boundaries: review and convert it to `items` before production instead of relying on TeX source newlines as visible line breaks.

Native code blocks use standard addvspace of 0.3 baselineskip for separation from surrounding paragraphs, with Fancyvrb's own vspace disabled so annotated minipages and ordinary code share the same spacing policy. Original blank lines inside the code remain untouched. The default style explicitly registers the selected CJK family for monospaced code; custom templates must also define a suitable CJK monospaced family when they contain Chinese code/comments. A diagnostic default-template fixture is not source-fidelity evidence for a new book, and none of these defaults replaces per-book template admission.

## Source-reviewed math grouping

`--math-presentations /absolute/math.json` reads `{source_sha256,groups:[decision,...]}`; `math_presentation.py` and the production exporter verify member original text/source-image identity and explicit source_checked review. `kind` is aligned_rows or labeled_display: the former uses ordered block_ids and rows=[{block_id,align_at,indent_em}] to express the source-reviewed common alignment point (Unicode math-body offset), and indent_em supports decimals within 0..6; the latter's single-member label must correspond to the original math prefix. Reading-layer label width normalization uses the actual field label_normalization={original,replacement,rule_id}, preserving numbering identity. Each member in the members mapping keeps text_sha256/source_sha256/source_image_sha256/evidence_path.

The production entry point combines only unnumbered math in the same chapter, continuous in reading order, and not consumed by another figure/table/code group; numbered formulas, external style spans, or footnotes are currently rejected, and you must not claim lossless support. Original blocks are unchanged; the sidecar's math_groups and each member's rendered_in_math_group_of record ownership. Real derivations and left-side step numbers still require inspecting the source image/output, and you must not mechanically merge based only on an equals sign at line end. In-book adaptation may explicitly call the same composer for reviewed exceptions, but must report the scope difference from the generic entry point. The composer's explicit label_bold projects only source-reviewed label bolding and does not automatically migrate external styles; this run's in-book adaptation using that field does not mean the generic entry point supports arbitrary style combinations. math_label_prefix can project in-source step numbers as left labels after verifying the original math-body prefix; preservation of trailing punctuation also has explicit limits, and it must not be used to swallow ordinary trailing body text.

## Source relationships and local geometry

An independently prepared source-first graphic inventory is required by production export (`--figure-inventory`), including explicit reviews of pages without graphics. The exporter re-runs the coverage audit against the current semantic blocks and selected assets and requires exact source-page scope. An incomplete or clipped graphic retains its visible source region and provenance; never infer the unseen continuation. Preflight can omit the inventory but cannot claim coverage acceptance.

Table presentation supports `caption_position=top|bottom`; choose from source evidence or an authorized restyling policy. Ordinary table rows keep template padding. For a reviewed staggered or sparse grid that cannot use ordinary row heights, `row_layout.baseline_offsets_em` supplies one increasing baseline per semantic row, starting at zero. Offsets follow the table font size; the exporter keeps full-size cell content and uses native row boxes. This mode excludes row spans, multipart tables, and additive `row_spacing_pt`. Check actual ink clearance, rules, and boundary padding in the rendered PDF; coordinates alone do not establish readability. Do not apply compressed baseline layouts to normal tables globally.

Keep short introductions with their following displays using native `samepage` and `needspace`; a reviewed `flow_presentation` can override the legacy adjacency heuristic. Group after layout composition so a consumed child cannot leave an unmatched environment. Long content can still require a different page-break strategy; inspect the actual final pages instead of treating a penalty as proof.

The bundled adapters let fontspec select the real bold/italic faces of the chosen Latin family; do not map Latin bold to an unrelated regular-weight sans family. Chinese Heiti emphasis remains a separate family choice. Verify available faces through the actual compile/dependency record; do not simulate bold to conceal a missing face.
