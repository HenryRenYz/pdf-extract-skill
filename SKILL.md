# PDF Extraction and Proofreading

First determine the result the user needs, the input scope, and the fidelity requirements, then choose a processing mode. Reuse existing choices; for unspecified routine details use the defaults below, and do not ask again about templates and covers for every new book.

| Mode | Requests it applies to | Process and delivery |
|---|---|---|
| `extract` | Extract text, formulas, and tables; generate Markdown/retrieval data | Check the native text layer, OCR if needed; preserve provenance, order, images, and uncertainties; no LaTeX template admission required |
| `proofread` | Proofread an existing extraction result against the source images | Independent source-image check; submit revisions with the original text hash; preserve raw output and unresolved items |
| `typeset` | Convert to editable LaTeX; typeset a reading PDF | Build the template, figures and tables, and numbering mapping on shared semantic data; after trial typesetting passes, run production export, compile, visual acceptance, and packaging |

Plain extraction defaults to `extract`; choose `typeset` when the user explicitly asks for LaTeX/PDF. Extraction fidelity and publication styling are different settings: accurately preserving the source image is a normal extraction result; arrange drawing only when the user requests editable figures or high-fidelity reconstruction. Typesetting uses an adjustable neutral template by default; keep the native full page when the cover is in scope and confirmed to be a cover. The user's format, model, time, cost, and page count take priority.

All participating models, including the coordinator, must support image input and the tools needed for their role. Worker execution requires a capability declaration (`--capabilities`); use a real source-page pilot to verify the selected service actually delivers images and tools. Installation and the current recommended model pairing are in [README](README.md).

## Workflow

1. **Check the source.** The original file is read-only; verify the real page count, physical pages and printed pages, rotation, text layer, layout, and image sharpness. Identify PDFs by file hash; identify a numbered PNG directory by the complete page set and file hashes. The same path does not mean the same content. When source pages or printed pages are discontinuous in an excerpt, preserve the break: do not splice body text, and do not fill in content from another version.
2. **Prepare and choose a route.** Use `scripts/prepare_images.py` to generate the overview, native overlapping tiles, and coordinate manifest. The overview only locates; read small text in tiles/crops. Use `--capabilities` to declare the backend capabilities and image budget for this run, and first run a trial on a real page; do not reuse the historical limits of any single model. When the text layer is reliable, use `scripts/native_text.py` to generate a native draft, then check formulas, fonts, and reading order against the source image; garbled text, Type3, control characters, or missing text cannot be fixed by global replacement. For scans, you can first try local layout OCR (currently `local_ocr.py` is a MinerU transformers adapter), or go directly to visual recognition. For other engines, keep the native output and use `import_drafts.py` to import it explicitly as an unreviewed draft; this does not mean their inference engine has been integrated. See [Inputs and routes](references/workflow.md).
3. **Small sample, then scale.** First verify the CLI, image delivery, and data contract on one real page. Page jobs write only JSON by default, and text and math content must be based on the source image. Use `run_page_jobs.py --mode extract|proofread|typeset` for bounded dispatch; without `--execute` it only prepares. OpenCode omits `--model` to use the user's configured default model, or you can specify a model explicitly; do not modify global configuration. Each page gets an independent job and attempt, and failures are not retried automatically by default; a timed-out finished product can be checked against independent source images and accepted with an explicit recovery receipt, while the failure record is kept. Recovery verifies the source, prompt, tools, draft, actual artifacts, and model identity. For stage fingerprints, external drafts, and cross-version zero-call reuse, see [Runtime and reuse](references/runtime-and-reuse.md). For execution entry points, see [Parallel dispatch](references/parallel-workflow.md) and [OpenCode](references/opencode.md).
4. **Verify semantics.** Block types, text, Unicode style spans, bbox, uncertainties, and changes use the [data contract](references/data-contract.md). Mark a genuinely blank page explicitly as `page_status=blank` and state the basis; do not invent text blocks. Use `canonicalize_pages.py` to save a normalized version without overwriting the original files, then use `assemble_book.py` to aggregate; cross-page merges, footnote attribution, and heading relationships need source evidence and are not decided automatically by OCR blocks, page numbers, or punctuation. Bottom-of-page content, answers, references, and indexes must not be lost because of an incorrect `footer` label or body-text heading.
5. **Calibrate styles and figures as needed.** Content proofreading and font inference are separate. Rule IDs contain no implicit action; `--rules` only supplies the rule library for review, while `--style-patches` applies explicit patches that have an original text hash, rule version, and scope; rule inference must not override an existing source-image confirmation. See [Typography](references/typography.md). Inventory all visible graphic regions independently first, including clipped fragments; reconcile that inventory with semantic blocks and selected assets (`--figure-inventory` for production export). Preserve the native structure of text/math/code, then choose the source image, native vector, or code reconstruction according to the target; preserve asset hashes and the actual admission decision. See [Figures](references/figures.md).
6. **Build a template only when typesetting is needed.** Both user templates and neutral templates need validation on real samples. Freeze the heading/paragraph/font/punctuation/list and figures-and-tables strategy for this run; font size, font family, page layout, and figure size are configuration for this run, not fixed facts for all documents. `format_preflight.py` verifies the actual template, transitive dependencies, render configuration, environment, and source/product evidence. For a small sample use `--preflight-mode` (at most 8 actual source pages, non-production); production export requires `--format-profile --template-ready`. When configuration changes, re-run acceptance for the affected parts, and do not re-OCR unchanged content. See [Template preflight](references/book-format-preflight.md). For code/grammar, read [Special text](references/code-special-text.md) first; for table of contents and numbering see [LaTeX export](references/latex-export.md) and [Contents](references/contents.md).
7. **Verify and deliver.** Report structural checks, compile checks, and content and visual checks separately. Check the actual output of this run and the source images; syntax that compiles, matching hashes, or a model saying it is done does not prove correct recognition. For typesetting, run the local self-check first, then the final integrated review; by default allow at most 3 revision rounds each for local and integrated review, and the user's budget can override this. After revisions, re-render the affected range; when the limit is reached, keep the candidate and `needs_review` and do not reclassify it as passing. `package_latex.py` verifies the identity of the exported files and carries the selected asset for each figure plus the actual build dependencies; `package_skill.py` includes only runtime resources when distributing the skill. For acceptance see [Evaluation](references/evaluation.md) and [Source package](references/source-package.md).

Before packaging a LaTeX source ZIP, ask once whether to include body-text font files, with **do not include** as the default. Reuse an explicit choice for the current book; if the optional question receives no answer, continue without fonts. Include fonts only after an explicit yes, together with their accompanying licenses and usage instructions; see [Source package](references/source-package.md) for the opt-in flags and font coverage checks. This choice is separate from the drawing-font dependencies and does not authorize changing fonts, the accepted TeX, or system font settings.

When selecting or adapting a LaTeX template, keep body content in native LaTeX commands and established package interfaces wherever they represent the source correctly. Put template-specific appearance in the class, preamble, or adapter; do not wrap ordinary headings, emphasis, equations, lists, or floats in new private commands. Any necessary body extension has one coordinator-owned, documented interface shared by workers, with its package-based alternatives and reason recorded. See [Template selection and body interfaces](references/template-selection.md) for candidate families, current integration limits, and the proposed adapter boundary.

## Fidelity and execution constraints

- Do not translate, summarize, add proofs, solve problems, or correct the original book according to common sense. Keep errata separately. For content you cannot read clearly, keep the original page/region and the candidates; do not drop an entire line because of uncertainty.
- Raw OCR, page images, published inputs, and old revisions are immutable. Text, styles, reading data, and LaTeX use the same semantic source; each body source block is counted exactly once, multi-page combinations keep all sources, and cross-page bboxes must not be fabricated.
- A model's self-reported `source_checked` or agreement is not independent confirmation; content evidence, style inference, and visual acceptance are recorded separately. Empty styles do not mean ordinary glyphs are confirmed. A scanned image cannot prove the exact font family, font size, or Unicode full-width/half-width code points.
- Check table data, merged cells, ruling line topology, and widths separately; never force a whole table into a grid, stretch it, or shrink the font size. Keep formulas and code as searchable, editable text when they can be expressed natively; explicitly record limitations for unsupported structures, and do not downgrade the type to hide the loss.
- A redraw records its deviation from the source. Faithful mode does not replace the source image with theoretical curves; reading normalization requires explicit authorization. Figure size, font, and line width are determined by this run's type area and readability; actually look at the size and occlusion in the final PDF. Photos and rendered images can keep the source image; when the user explicitly chooses to keep the source image, do not force a paid redraw.
- Each job/section/asset has only one writer per round. The coordinator merges patches; the number of agents, retries, and steps inside the CLI all count toward the budget. `--max-invocations` limits the number of CLI invocations, which is not the number of server requests or a cost cap; write partial/null for unknown usage, never zero.
- Use independent environments for dependencies; do not modify shared global environments, default models, or plugin configuration. The current core runtime needs Python 3.11+, Pillow, and PyMuPDF; local OCR, drawing, and TeX are on-demand dependencies, see `pyproject.toml` and `scripts/check_environment.py`.

Read reference material for the current step; do not load all past experiments. Test instructions, gold standards, and existing answers must not be given to a worker that performs extraction.
